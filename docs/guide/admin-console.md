# 管理控制台

管理控制台位于 `/console/admin`。`organizer` 可以管理所有比赛和裁判事务；`admin` 额外拥有用户、角色、平台设置和全局运维权限。所有授权都在 Nuxt 领域服务中重复检查，隐藏页面或按钮不是安全边界。

## 比赛与题目

管理员可以创建草稿比赛，配置 UTC 开始/结束时间、可见性、报名策略、队伍人数、分组、邀请码、封榜、赛后练习和 Writeup。发布前检查会把缺失题目、Flag、附件、动态实例参数和资源限制定位到具体资源。首期只能创建 Jeopardy 比赛，未知赛制和相关配置在 API、导入和数据库边界均被拒绝。

题库模板通过不可变版本演进。挂题时复制完整比赛题目快照，包括题面、附件引用、提示、Flag、计分和实例策略。模板后续更新不会改变已发布比赛；公平性字段只能通过显式修订命令变更，并产生版本、审计和客户端失效事件。

公告支持草稿、定时发布、修改和撤回。公共时间线只包含公告、题目/提示发布、首解、封榜和比赛阶段变化；管理、安全和运维事件只进入后台审计。

## 参赛、提交与 Writeup

参赛列表支持审核、拒绝、撤回和分组分配。接受时系统会重新校验参赛条件。已接受且未结束的比赛会锁定普通队伍成员变更，管理员纠正必须填写原因。

监控查询默认遮罩敏感答案，只显示正式/练习模式、结果、时间和关联资源。反作弊线索仅用于人工复核，不会自动处罚。正式成绩的修改必须写追加式计分调整或执行可审计的结果重算，不能覆盖原始提交和解题事实。

Writeup 支持版本化保存、截止时间、提交、审核、管理员纠正与批量导出。附件下载每次都由控制面重新授权。

## 监控

专用页面 `/console/admin/monitoring` 从 PostgreSQL 读取以下事实投影：

- 提交与反作弊线索；
- 实例与 `instance_jobs`，包括 Worker 观察是否陈旧；
- 公告、站内通知和邮件投递；
- Writeup 与不可变审计。

筛选条件包括比赛、题目、队伍、状态和返回条数。页面不得显示 Flag、完整提交答案、Cookie、一次性令牌、邮件 payload、Provider 凭据或内部集群地址。

## 受控运维

专用页面 `/console/admin/operations` 仅允许 `admin` 使用。每次操作都要选择目标、填写至少 10 个字符的原因、明确确认并提供幂等键：

- `dead_letter_replay`：重放实例死信任务；
- `instance_reconcile`：触发实例对账；
- `session_invalidate`：使用户全部旧 Cookie 失效；
- `result_recalculate`：从权威事实重放比赛结果。

操作结果和重复请求语义都会写审计。生产运维不得用直接 SQL 更新替代这些命令。

## 用户、设置与审计

`admin` 可管理用户状态和全局角色。封禁、角色变化、改密和找回密码会递增 `session_version`。账号安全事件创建站内通知；外部邮件由事务 Outbox 幂等投递，SMTP 故障不会回滚已完成的安全事务。

平台设置只保存类型化的品牌、Logo、主题、默认语言、公开注册和首期密码登录配置。Session、数据库、对象存储、邮件和实例密钥必须来自部署 Secret，不能写入设置表。

审计记录不可变，覆盖用户、角色、比赛、题目、成绩、实例、设置和运维写操作。审计默认保留一年；安全日志默认保留 90 天；正式比赛事实长期保留。

详细值班流程见 [运维 Runbook](../operations/runbook.md) 和 [应急响应](../operations/incident-response.md)。
